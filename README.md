# LeaseFIT MVP

Рабочий кабинет риелтора: приглашение → профиль бизнеса → уточняющие вопросы → найденные помещения → проверка и сравнение → клиентский PDF. Django 5.2 LTS, PostgreSQL 16, серверные шаблоны, небольшой JavaScript, ReportLab, Gunicorn, Docker Compose. Русский интерфейс и тёмная палитра `#0B1220 / #111A2B / #162033 / #24324A`.

Источник P0 — приложенная `LeaseFIT_Specifikatsiya_Saita_i_MVP.docx`, версия 1.0, ноябрь 2026. Прямая просьба пользователя задаёт границы: существующий лендинг и `BaClock/LeaseFit` не меняются, публикация не выполняется. Указания о согласованиях, Figma и распределении команды внутри Word рассматриваются как контекст документа, а не дополнительные команды пользователя. Старые концепции и заметки не расширяют P0.

Текущая навигация и оформление отчёта обновлены по запросу от 17 ноября: [описание изменений и проверок](docs/UX_UPDATE.md).

## Локальный запуск

Нужны Git, Docker и Compose v2. Рекомендуется 4 ГБ RAM и 10+ ГБ свободного диска (при Docker VFS — больше).

```bash
git clone https://github.com/BaClock/leasefit-mvp.git
cd leasefit-mvp
python3 scripts/init_env.py
docker compose up -d --build
docker compose exec web python manage.py seed_demo
```

Откройте <http://localhost:8000/login>. Команда выдаст случайные пароли **только при первом создании**:

- `leader@example.invalid` — руководитель;
- `agent@example.invalid` — риелтор с тремя учебными вариантами;
- `/invite/<token>` — одноразовая ссылка активации нового риелтора, действует 7 дней.

Повторный `seed_demo` не перезаписывает запросы, сведения и пароли. `--fresh-invitation` создаёт отдельное вымышленное приглашение для повторного браузерного теста. Учебные данные допускаются по умолчанию только при `DEBUG=1`.

Порт можно изменить через `WEB_PORT` в `.env` (в среде проверки использован 8010). Проверка готовности: `curl -f http://localhost:8000/healthz`. Статус: `docker compose ps`; журнал: `docker compose logs --tail=100 web`.

Данные, исходные вложения и байты выпущенных PDF хранятся в PostgreSQL, в именованном томе `postgres_data`. `docker compose restart`, `down` и последующий `up` сохраняют данные. **Не используйте `down -v` для рабочей базы.**

## Адреса для существующего лендинга

| Кнопка | Локально | После отдельного развёртывания |
|---|---|---|
| Войти в кабинет | `http://localhost:8000/login` | `https://<домен-кабинета>/login` |
| Подать заявку на пилот | `http://localhost:8000/pilot` | `https://<домен-кабинета>/pilot` |

Публичный учебный пример: `/example`. Условия обработки учебной заявки: `/privacy`. Корень этого приложения перенаправляет во вход/кабинет; лендинг здесь не дублируется. Домен намеренно не назначен, DNS и кнопки лендинга не изменены.

## Проверка

```bash
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose exec web python manage.py test --verbosity 2
```

Тесты создают отдельную `test_leasefit` и удаляют её после выполнения, не меняя учебные запросы. Пользователь БД должен иметь `CREATEDB` для тестового запуска; рабочий пользователь может быть ограничен, тесты выполняются отдельно.

Сквозной браузерный тест создаёт **дополнительные вымышленные записи** в учебной базе:

```bash
python3 -m venv .test-venv
.test-venv/bin/pip install -r requirements-dev.txt
# Если Chromium не установлен: .test-venv/bin/playwright install chromium
# Можно передать установленный Chromium через --executable /path/to/chromium.
docker compose exec web python manage.py seed_demo --fresh-invitation
.test-venv/bin/python scripts/browser_smoke.py \
  --base-url http://localhost:8000 \
  --invite /invite/ТОКЕН_ИЗ_КОМАНДЫ \
  --executable /usr/bin/chromium
```

Результаты и покрытие — [docs/TEST_RESULTS.md](docs/TEST_RESULTS.md). Скриншоты и PDF браузерного теста пишутся в `artifacts/`, исключённый из Git.

## Устройство P0

- Риелтор видит и меняет свои запросы. Руководитель читает запросы агентства, приглашает/отключает риелторов; чужие запросы не редактирует. Принадлежность и действующий доступ проверяются на каждом маршруте чтения, записи и скачивания.
- Приглашение привязано к email/агентству; активация задаёт пароль, закрытая сессия сохраняется на сервере. Глубокий разрешённый адрес сохраняется при входе. Восстановление пароля использует Django; локально письмо выводится в журнал, для рабочего пилота нужен SMTP.
- Обязательный минимум черновика: название, город, формат. Требования задаются операторами ≥, ≤, диапазон и да/нет; есть желательные и неприменимые условия. Условия кофейни — учебный пример, не норматив.
- Для каждого инженерного наблюдения хранятся значение, единица, область сведений, источник, дата, автор, подтверждение и основание. Для всех введённых коммерческих сумм и расчётной площади задаётся общий источник с датой/статусом; суммы в ₽, период и единица видны в полях. Для отдельных уточнений можно дополнительно вести наблюдения. История конфликтующих источников сохраняется после выбора актуального.
- Только подтверждённое актуальное значение для помещения в той же единице может пройти проверку или дать блокер. Объявление, архив, комната и здание не подтверждают всё помещение. Разные незаменённые значения оставляют конфликт до его явного разрешения.
- Месячные и разовые затраты считаются отдельно; депозит не входит в месяц. Пустая сумма отличается от 0. Неизвестные платежи, НДС и конфликт ставки/месячной суммы дают неполный итог. НДС сверх цены начисляется только на базовую аренду по введённой ставке; прочие платежи вводятся уже с налогами.
- Проверка сохраняет версии профиля, карточки и правил. Правки требуют пересчёта; скрытое поле версии предотвращает перезапись из устаревшей вкладки. Изменения блокируют родительский запрос транзакцией PostgreSQL. Совместное редактирование не входит в P0.
- Проверка 1–4 вариантов и сравнение 2–4 вариантов одного запроса: таблица на широком экране, карточки до 768 px. В режиме различий одинаковые обязательные блокеры и неизвестные сохраняются.
- Отчёт на 1–4 варианта содержит снимок критериев, источников, расчётов и выводов, исключает внутренние заметки и исходники. Блокер обозначается как отсеянный вариант, неизвестный — только условно рассматриваемый. Существующие PDF не перегенерируются при скачивании. Новый результат получает новую версию; повторная отправка/одинаковый снимок возвращает существующую.
- Вложения PDF/JPG/PNG до 20 МБ проверяются по содержимому и сохраняются в закрытой БД. Публичного `/media` нет. Скачивание требует доступа к запросу, ответы имеют `private, no-store`.
- `AuditEvent` фиксирует автора, агентство, действие, ID ресурса и время без контактных данных/текста отчёта. Оператор работает с заявками через Django admin; обычные пользователи туда не допускаются.

## Данные и границы

См. [docs/DATA.md](docs/DATA.md). Существующая БД не подключалась. XLSX — читаемая выгрузка, не контракт схемы или готовый ORM-источник.

Развёртывание с HTTPS, SMTP, резервными копиями и восстановлением: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Ограничения: [docs/LIMITATIONS.md](docs/LIMITATIONS.md).

В левом меню «Помещения» собраны все варианты, доступные по правам. Уточняющие вопросы и кнопки «Далее» ведут по запросу без вкладок; выпуск отчёта и выбор его дополнительных параметров находятся на странице сравнения. Парсинг доступен руководителю/администратору как заглушка.
