# Ограничения пилота

- Публичное размещение, DNS и изменения существующего лендинга не выполнялись. `/privacy` — проект условий только для вымышленных данных; до реального пилота оператор должен утвердить реквизиты, основание, сроки хранения, обработку согласий и порядок удаления.
- Приглашение создаётся руководителем, ссылка передаётся сотруднику вручную. Автоматическая рассылка приглашений не реализована. Восстановление пароля работает через стандартный Django email backend; локальный backend пишет письмо в журнал, SMTP нужно настроить отдельно.
- Смена руководителя и создание агентства — операционный процесс через management-команду / доверенного оператора. В UI руководитель управляет доступом риелторов; отключение руководителей запрещено. Перенос владельца и совместное редактирование — P1.
- Требования и факты сопоставляются по идентификатору справочника. Стандартные единицы фиксированы. Миграция нормализует эквивалентные записи (`m2`/`м2` → `м²`, `kw` → `кВт`). Пересчёт Вт ↔ кВт не выполняется. Неоднозначные старые условия сохраняются для ручного уточнения. Шаблоны содержат рекомендации, а применимые нормативные пункты проверяются в предварительном чек-листе. [Реестр нормативов](REGULATORY_REQUIREMENTS.md).
- Расчёт относится к введённым условиям, а не к прогнозу бизнеса. Коммерческие поля используют общий источник/дату/подтверждение для введённого набора сумм и расчётной площади. Раздельные источники можно дополнительно фиксировать наблюдениями. НДС сверх цены поддерживается как процент на базовую аренду; остальные регулярные суммы вводятся с налогами. Не моделируются несколько налоговых баз, будущие периоды, индексация и каникулы как денежный поток.
- «Только различия» сокращает совпадающие нейтральные технические требования; финансовый блок остаётся для понимания бюджета. Совпадающие обязательные неизвестные и блокеры сохраняются.
- Изменение профиля или сохранение карточки требует пересчёта; продолжение по профилю без правок не меняет его версию; смена стадии также консервативно меняет версию запроса. История исходных наблюдений/проверок и старые PDF сохраняются.
- Формирование PDF синхронное, 1–4 варианта, без фоновой очереди, публичных ссылок и отправки клиенту из приложения. Повтор одинакового снимка возвращает уже выпущенную версию. Отчёт — альбомная компоновка с обзором и подробными разделами по вариантам.
- Вложения до 20 МБ лежат в PostgreSQL `bytea`: удобно для целостного резервного копирования пилота, но не для большого документооборота. Формат проверяется, антивирус и OCR не подключены. Для масштаба потребуется закрытое объектное хранилище и отдельная процедура проверки файлов.
- Нет SSO/MFA, прикладного CAPTCHA или встроенного распределённого throttling. Для внешнего доступа обязательны HTTPS, защищённая сеть приложения и ограничение частоты на reverse proxy (пример Nginx приложен). Операционный доступ к БД/резервным копиям остаётся доверенным.
- Метрики SLA и пользовательская полезность на реальных агентствах не подтверждены. Есть аудит ключевых событий без содержимого документов, но нет отдельной аналитической панели или исследований эффективности.
- Существующая внешняя БД и CRM не подключены. Есть внутренний каталог агентства. Массовый парсинг, оплата, ML, геоаналитика и расчёт метрик этапов P1/P2 отложены. Рейтинг 0–100 отражает профиль и бюджет. Безубыточность и стресс рассчитываются по допущениям клиента. Техническая и юридическая экспертиза остаётся за специалистами. [Методики метрик](METRICS_METHODS.md).

- Новое меню и отчёт описаны в [UX_UPDATE.md](UX_UPDATE.md). Парсинг и карта лидов пока обозначены как будущие модули: данные не загружаются, показатели и карты не рассчитываются.

- Общая карточка редактируется сотрудниками своего агентства. Автоматического объединения дублей нет; совпадение адреса вызывает предупреждение. Поиск и технические фильтры рассчитаны на учебный объём; пагинация, индексы поиска и нагрузочная оптимизация потребуются при росте каталога. Площадь и цена в фильтрах — введённые коммерческие данные; технические фильтры принимают только подтверждённые текущие факты помещения без конфликтов.
- Прежние вложения остаются закрытыми по исходному запросу. Новые технические документы видны агентству; интерфейс предупреждает не загружать в общий каталог клиентские документы/комментарии. Откат заполненного общего каталога на старую схему допускается только восстановлением проверенной резервной копии с прежней версией кода.
