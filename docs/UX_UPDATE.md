# Обновление рабочего сценария · 17 ноября 2026

Прямой запрос пользователя изменяет навигацию предыдущего P0. Файл `example (1).pdf` использован как визуальный ориентир: альбомные страницы, боковое оглавление, крупные карточки, светлые таблицы, зелёные заголовки и синий акцент. Его цифры, карты, бренды и утверждения не перенесены как данные LeaseFIT.

## Реализовано

1. **Помещения в левом меню** (`/app/premises`): все ранее добавленные варианты из доступных запросов, включая архивные; поиск, переход к карточке, добавление нового через выбор своего рабочего запроса. Риелтор видит свои варианты, руководитель — агентство. Это внутренний список найденных вариантов, не публичный каталог.
2. **Последовательный маршрут**: профиль → уточнения → помещения → проверка и сравнение. Индикатор шагов не содержит ссылок. Переходы вперёд — кнопками «Далее», есть явные кнопки возврата. Прежние вкладки убраны.
3. **Уточнения после профиля** (`/app/requests/{id}/refine`): бюджет, районы, площадь, мощность, вода, отдельная вытяжка. Уже заданные технические параметры не повторяются. Ответ с числом/условием и выбранной важностью становится требованием; пустой ответ сохраняет неизвестность. «Не требуется» задаёт неприменимое условие. Уточнение профиля делает старые оценки устаревшими; простое продолжение без правок этого не делает.
4. **Один экран проверки и сравнения**: выбор 1–4 вариантов, серверный пересчёт, причины, источники, обязательные вопросы, отдельная экономика. При одном варианте доступна его проверка и одиночный отчёт; сравнивать можно со второго.
5. **«Добавить в отчёт — параметр»**: выбор желательных критериев, расшифровок месячных/разовых расходов, стрессового сценария и будущего раздела карты лидов. Выбор сохраняется в БД отдельно от технического профиля; не устаревает проверка. Обязательные требования, блокеры, неизвестные, бюджетный итог и источники исключить нельзя. Версия состава предотвращает перезапись из устаревшей вкладки. Комментарий остаётся в закрытой сессии при изменении состава.
6. **Формирование отчёта внутри сравнения**: встроенный предпросмотр, кнопка «Сформировать отчёт», список сохранённых версий и скачивание. Отдельной вкладки отчётов нет. Старые `/checks` и `/reports` перенаправляют в общий экран; скачивание старых PDF сохраняет прежние байты.
7. **Новый PDF**: альбомный формат 1080×608, боковое оглавление, обзор вариантов, карточки показателей, технические причины и вопросы, таблицы расходов, источники и допущения. Карта лидов — явно подписанный будущий модуль без вымышленных показателей/точек; реальной геоаналитики пока нет.
8. **Кнопка парсинга**: доступна руководителю и администратору. Экран `/app/parser` показывает состояние «В разработке», поясняет следующий этап и предлагает ручное добавление. Сетевой загрузки объявлений, извлечения значений или автоматического подтверждения нет. Сервер закрывает экран от риелтора и деактивированного руководителя; superuser без агентства может открыть заглушку из admin.

## Обновление существующего запуска

```bash
git pull --ff-only
docker compose up -d --build
```

Миграция `0004` добавляет поля состава отчёта и его версии. Существующие данные, оценки, файлы и выпущенные PDF не переписываются. Лендинг и его репозиторий не менялись; кнопки по-прежнему ведут на `/login` и `/pilot` домена кабинета. Публикация не выполнялась.
